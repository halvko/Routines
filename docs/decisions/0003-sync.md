# 0003: Hand-rolled sync: an outbox on the device, one ordered log per user

Accepted, 2026-11-06.

## Decision

Replicache-style, written here (a few hundred lines), not a library:

1. The device applies a change locally through the core and appends it to an
   **outbox** (`{id, name, args, clientSeq}`).
2. It pushes the outbox to the server. The server applies each change with
   **the same core**, gives it the next number in that user's log, stores it,
   and tells the user's other devices.
3. Devices pull everything after the last number they have, take it as their
   new base, and replay their still-unsent changes on top.
4. Changes are idempotent by `(clientId, clientSeq)`, so retries are safe.

How data merges:

- **Routine templates and backlog items:** last write wins per field. Lists
  are ordered by sort keys, not array positions.
- **Run state** (step done, skipped, placed): an append-only event log; state
  is a fold over it.

The server is the source of truth; a device is a cache plus an outbox (iOS may
evict web storage).

## Why

- One user, a few devices: real conflicts are rare and simple.
- One writer per user orders everything, so all devices converge.
- No library in the research fits: Zero has no offline writes, InstantDB is
  shutting down, PowerSync and Electric need Postgres and an always-on
  service, LiveStore is pre-1.0. CRDT libraries mainly pay off for
  collaborative text.

## Rules out

- Editing shared state without going through the core's `update`.
- Array positions as identity in synced data.
